# TicketPlus 購票小幫手（Chrome 插件）

遠大售票（ticketplus.com.tw）購票輔助工具，功能：

1. **自動選場次** — 活動頁上依關鍵字（日期／時間）自動點該場次的「立即購買」
2. **快速填票數** — 選票頁上依設定自動連點「＋」把票數加到指定張數
3. **自動勾選同意條款** — 勾選「我已經閱讀並同意 會員服務條款 與 隱私權政策」
4. （可選）**自動點「下一步」** — 預設關閉，避免誤送出

## 安裝方式

1. 開啟 Chrome，網址列輸入 `chrome://extensions`
2. 右上角開啟「開發人員模式」
3. 點「載入未封裝項目」，選擇本資料夾（`ticketplus/`）
4. 完成後工具列會出現 🎫 圖示

## 使用方式

1. 點工具列的插件圖示，開啟設定：
   - **啟用自動模式**：勾選後，進到活動頁／選票頁會自動執行
   - **場次關鍵字**：例如 `08-14` 或 `19:30`，留空表示選第一個可購買場次
   - **票種與張數**：一行一條，格式「票種關鍵字 張數」，例如：
     ```
     全票 2
     身障票 1
     ```
     用 `*` 代表第一個票種（例：`* 2`）
   - **自動勾選同意條款**：預設開啟
   - **自動點下一步**：預設關閉，建議自行確認後手動送出
2. 按「💾 儲存設定」
3. 進入活動頁面（需先登入會員），插件會自動執行；也可以按「▶ 在目前分頁立即執行」手動觸發
4. 右下角會有黑色浮動提示顯示插件做了什麼

## 排隊狀態顯示（v1.1.0 新增）

進入排隊時，右下角會出現狀態面板，把網站原本沒顯示的排隊資訊攤開來：

- **⏳ 排隊中（不是被擋）** — 收到 `errCode 137`，代表本輪沒抽中，會在倒數結束後自動重試
- **✅ 已排到，鎖票中** — 收到 `errCode 00`
- **⛔ 流程已中止** — 收到其他錯誤碼，網站已把 `window.isEnquene` 關掉，**必須重新整理頁面**才能再排

面板同時顯示已排隊次數、錯誤碼與中文意義、下次重試倒數秒數。

### 為什麼需要這個

`enqueue` 不是傳統的排隊，是**每輪獨立的抽籤**（回應字面是 `is not hit`）。它不回傳名次、不回傳前面有幾人，等再久也不會累積優先權。網站前端在 `137` 時只是靜靜轉圈，使用者無從分辨「還在等」和「流程已死」，這個面板就是補上這個區別。

### 錯誤碼對照（取自網站前端 `chunk-3225fb1b` 的 errorHandler）

| 代碼 | 意義 | 後續 |
|---|---|---|
| `00` | 排到了 | 進入鎖票 |
| `137` | 本輪未抽中 | 依 `waitSecond` 自動重試（未給則 15 秒） |
| `101` | 操作出現問題 | 流程中止 |
| `110` | 流量管控中 | 流程中止 |
| `112` / `115` / `121` | 票種售完或超過購票張數限制 | 流程中止 |
| `113` / `116` | 無座位／無連續座位 | 流程中止 |
| `114` | 購票逾時 | 流程中止 |
| `124` / `125` | 序號錯誤／已使用 | 流程中止 |
| `135` / `136` | 驗證碼錯誤／過期 | 流程中止 |
| `999` | 網路連線失敗（前端自產） | 流程中止 |

### 實作方式

`inject.js` 在頁面主環境（`world: "MAIN"`）攔截 XHR/fetch **唯讀觀察**購票 API 的回應，再用 `postMessage` 轉給 content script 顯示。**不攔截、不重送、不改變任何請求或重試頻率** — 純粹把網站原本就在做的事顯示出來。

## 注意事項

- 網站是 Vue SPA，插件用「文字關鍵字＋圖示」定位元件，官方改版時可能需要調整 `content.js` 的 selector
- 本工具僅加速個人購票流程的表單填寫，**不會**也**不應**用於繞過驗證碼或大量搶票
- 送出訂單前請自行確認票種、張數與金額

## 檔案結構

| 檔案 | 用途 |
|---|---|
| `manifest.json` | 插件設定（MV3，只在 ticketplus.com.tw 生效） |

| `popup.html` / `popup.js` | 設定介面 |
